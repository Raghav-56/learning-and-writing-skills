# Self-explanation

Have the learner connect a claim or step to the principle that makes it valid. Judge the reasoning, not fluency or the use of familiar terminology.

1. Select a consequential step or a compact concept. Ask why it follows, when it applies, or what would change under a different assumption. Keep the requested explanation proportional to the goal.
2. Evaluate the actual account. Identify missing conditions, circular reasoning or a mismatch between an analogy and the mechanism. Use `answer-evaluator` when available. Credit valid alternative explanations.
3. Supply a concise correction if needed. A [counterexample](../learning-counterexamples/SKILL.md) can expose an overgeneralized claim; a [trace](../learning-traces/SKILL.md) can reveal a hidden state transition.
4. If useful, check one changed case through [transfer](../learning-transfer/SKILL.md). End when the explanation is adequate for the stated goal, or mark the remaining point unassessed if practice is declined.

Example: instead of asking for Dijkstra's definition again, ask why a selected vertex can be finalized under the stated edge-weight assumption. If the learner has never seen the procedure, use [source study](../learning-source-study/SKILL.md) first.

If the user asks you to explain, give the explanation before suggesting teach-back. This skill is not permission to replace an answer with questions. A convincing immediate explanation is local evidence, not proof of delayed retention.
