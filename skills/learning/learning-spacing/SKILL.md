# Spacing

Own when to revisit material. [Retrieval](../learning-retrieval/SKILL.md) owns what the learner does during a review. A review queue should fit the learner's available time and exam horizon.

1. Read the current records if present. Prefer overdue weak material, recurring mistakes and prerequisite knowledge over expanding the deck indiscriminately. Distinguish forgotten knowledge from a concept that was never understood.
2. Propose a short review interval after a failed or heavily helped attempt; extend intervals after successful independent recall. For a new queue, next day, several days later and about a week later are starting heuristics, adjusted to performance and the exam date. There is no universal optimal sequence.
3. Write prompts that test one clear target while retaining necessary context and assumptions. Include application or condition questions for conceptual material. Long procedures still need full problems, not only atomic cards. Have the learner review generated cards before relying on them.
4. Return the next review items and dates or intervals. Explain any prioritization briefly. If the queue exceeds the time budget, trim duplicates and low-value additions and repair prerequisites.

A calendar plan is not evidence that a review happened. Create reminders, edit an external scheduler or export a deck only when requested. Keep dates relative when the actual current date is unavailable. Persist only through existing course records or requested artifacts, following [assessment and continuity](../learning-router/references/assessment.md).

Use [source study](../learning-source-study/SKILL.md) or [error repair](../learning-error-repair/SKILL.md) for misunderstandings before repeating them. Read [GATE adaptation](../learning-router/references/gate.md) for GATE and [research](../learning-router/references/evidence.md) for spacing evidence and practitioner card-writing guidance.
