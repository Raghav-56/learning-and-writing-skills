# Error repair

Start from the submitted work and preserve the original attempt. `answer-evaluator`, when available, owns correctness judgment and marks; this skill owns what to teach and retest after that judgment.

1. Read the full question, assumptions, submitted working and authoritative answer if available. Locate the first consequential error and preserve valid reasoning. If evidence is ambiguous, give a provisional diagnosis and say what is missing.
2. Classify only as far as the evidence supports: missing prerequisite, forgotten fact, misunderstood condition, wrong method selection, execution slip or misread question. Use that diagnosis to choose the repair.
3. Explain the cause and correct it with the smallest useful demonstration. Use a [counterexample](../learning-counterexamples/SKILL.md) for a false general rule, a [trace](../learning-traces/SKILL.md) for a state mistake, or a [worked example](../learning-worked-examples/SKILL.md) for an unfamiliar procedure.
4. If practice fits the request, give a fresh repair question that cannot be answered by copying the shown answer. Record the repair separately. Use [spacing](../learning-spacing/SKILL.md) to propose a later retest for recurring or consequential errors.

Return the root error, correction, observed repair result and remaining gap. A corrected original answer is not a new independent success. A minor notation slip may need only a correction; match the intervention to the error rather than expanding every mistake into a lesson.

Honor a requested complete solution. Use the existing course's scoring and record format under [assessment](../learning-router/references/assessment.md), without inventing an official partial-mark scheme. Read [GATE adaptation](../learning-router/references/gate.md) for exam use. [Research](../learning-router/references/evidence.md) supports component choices, not a separately validated error-log system.
